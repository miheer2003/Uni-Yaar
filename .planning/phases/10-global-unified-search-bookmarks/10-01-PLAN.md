# Plan 10-01: Backend Unified Omnisearch Aggregator & Bookmarks API

## Goal
Implement a high-performance backend search aggregator that queries across campus entities (Buildings, Rooms, Faculty, Food Outlets, Events, Announcements, Maintenance Notices) in a single request, returning standardized search results with deep links, coordinates, and metadata. Also provide user bookmark endpoints.

## Key Changes
1. **DTOs & Models**:
   - `SearchItemType`: `BUILDING`, `ROOM`, `FACULTY`, `FOOD_OUTLET`, `EVENT`, `ANNOUNCEMENT`, `MAINTENANCE`.
   - `SearchResultItem`: id, type, title, subtitle, details, badge, targetUrl, buildingId, roomId, latitude, longitude.
   - `SearchGroupResponse`: query, totalResults, results (list of SearchResultItem).
2. **SearchService & SearchController**:
   - Multi-repository query with case-insensitive partial matching across 7 domains.
   - Limit and sort results by relevance.
   - Endpoint: `GET /api/search?q={query}`.
3. **Bookmarks**:
   - `Bookmark` entity: id, user, itemType, itemId, title, subtitle, targetUrl, createdAt.
   - `BookmarkRepository`, `BookmarkService`, `BookmarkController` (`GET /api/bookmarks`, `POST /api/bookmarks`, `DELETE /api/bookmarks/{id}`).
4. **SecurityConfig**:
   - Allow public access to `GET /api/search`.
